# Google Home daily-summary shortcut

For first-time installation and speaker setup, follow the
[Google Home connection checklist](GOOGLE_HOME_SETUP.md).

Create a script from the shipped
[daily-summary blueprint](../examples/blueprints/script/track_things/daily_summary.yaml).
It calls `track_things.get_daily_calendar`, then `tts.speak` with the returned
summary. The day follows Home Assistant's timezone. A zero-entry day is a valid
spoken summary; failures are never converted into an empty calendar.

This is a fixed shortcut, independent of the conversation-engine decision in
[#25](https://github.com/MSpiechowicz/track-things-home-assistant/issues/25).
It does not receive arbitrary spoken parameters or follow-up replies. It always
uses the configured output speaker, even when invoked from a different device.
Google speaker identity does not select an account, subject, or output.

## Set up the script

You need Home Assistant 2026.9 or later, a configured Track Things account, a
working TTS entity, and a media-player entity capable of playing that TTS output.
Choose the desired Nest Audio or Nest Hub media-player entity explicitly; device
compatibility and successful audio delivery must be checked in your installation.
The integration's [calendar action guide](CALENDAR_ACTIONS.md) describes the read
contract and account selection.

1. Copy `examples/blueprints/script/track_things/daily_summary.yaml` into your HA
   configuration directory at `blueprints/script/track_things/daily_summary.yaml`.
2. Under **Settings → Automations & scenes → Blueprints**, reload blueprints if
   necessary. Create a script from **Track Things daily summary**.
3. Select the Track Things account, a TTS entity, and the fixed output speaker.
   Choose `en` or `pl` for the summary and a matching language code accepted by
   the TTS provider (for example `en`, `en-US`, or `pl`, depending on the provider).
   These are saved settings; Google does not supply them with each invocation.
4. Save the script as **Track Things daily summary**. Confirm its entity ID is
   `script.track_things_daily_summary`, or use its actual ID in the exposure setup.
5. Run the script in HA first and inspect its trace. The speaker must be able to
   retrieve the audio URL generated by HA/TTS. Resolve playback issues before
   adding Google exposure.

For YAML-managed scripts, place this entry in `scripts.yaml` after copying the
blueprint. Replace all three example IDs with your real selections:

```yaml
track_things_daily_summary:
  alias: Track Things daily summary
  use_blueprint:
    path: track_things/daily_summary.yaml
    input:
      config_entry_id: YOUR_CONFIG_ENTRY_ID
      tts_entity: tts.YOUR_TTS_ENTITY
      output_speaker: media_player.YOUR_SPEAKER
      summary_language: en
      tts_language: en
```

Your `configuration.yaml` should include `script: !include scripts.yaml` if that
is how your existing scripts are managed. Merge with existing configuration,
validate configuration, and reload scripts. Do not create duplicate `script` keys.
The script uses `mode: single`: another invocation while it is running is ignored
with an HA warning, preventing overlapping runs of this script.

## Expose only the intended shortcut

Choose the exposure method matching your existing Google integration:

- **Home Assistant Cloud:** use **Settings → Voice assistants → Expose** and
  enable Google Assistant for this script only among the Track Things entities.
  Review any previously exposed scripts; creating a blueprint is not an exposure
  allowlist. Keep helper scripts and unrelated Track Things actions unexposed.
- **Manual Google integration:** merge the
  [selective-exposure example](../examples/google_assistant_daily_summary.yaml)
  into your existing `google_assistant` configuration. Preserve the existing
  project and authentication settings. `expose_by_default: false` means each
  entity you intend to expose must have an explicit `expose: true` entry. The
  standalone example exposes only `script.track_things_daily_summary`; review
  existing explicit entries when merging. Restart HA after changing this config.

Assign the script to an HA area if other members of the Google household will
invoke it. Sync Google devices after exposure, using “Hey Google, sync my devices”
or `google_assistant.request_sync` for a manually configured integration.
No new Google project, subscription, or credentials are required if your existing
Google integration already works. Follow the official integration instructions
below if you have not configured that connection yet.

In Google Home, create a routine with an English voice starter such as
“What's my Track Things summary”. Add an action to activate the exposed
**Track Things daily summary** scene/script; where the routine editor uses a
custom command, use “Activate Track Things daily summary”. Save and invoke the
routine. Menu labels and scene availability depend on the Google Home app/account;
verify direct activation before troubleshooting the routine.

An English Google starter can invoke a Polish summary if the script and TTS
provider are configured for Polish. That does not demonstrate Polish speech
recognition on Google speakers. It also does not demonstrate full dialogue on
Gemini for Home or forward a Nest microphone into HA Assist.

## Outcomes and recovery

| Situation | Script behavior |
| --- | --- |
| Populated day | Speaks the action's summary once on the fixed speaker. |
| Empty day | Speaks the action's localized zero-entry summary. |
| Calendar/backend failure | Attempts a generic English/Polish failure announcement and ends with a failed trace. No previous summary is reused. |
| Missing/blank summary response | Uses the same failure path, never an empty success. |
| TTS action failure | Ends with an error; no automatic retry or alternate output. Inspect the trace and TTS/media-player configuration. |
| Audio accepted but inaudible | HA may report success before physical playback. Check mute/volume, connectivity, and TTS URL reachability on the selected speaker. |

The failure announcement contains no backend error details. Summaries can contain
tracker and subject names; choose an appropriate output location. The script
passes only the summary to TTS, not raw entries or notes. The TTS provider receives
the spoken text according to its own processing policy.

Google may acknowledge activation before the script finishes. That acknowledgement
is not confirmation that the calendar read or audio playback succeeded. Use the
spoken result and HA script trace. If the backend remains unavailable, restore
connectivity or reauthenticate Track Things before retrying. Calendar reads retain
the integration's normal short-lived cache behavior.

## Verification

From the repository's installed test environment:

```sh
python -m pytest -q tests/test_google_summary_example.py
python -m ruff check .
python -m ruff format --check .
python scripts/check_file_sizes.py
python -m pytest -q
```

Tests load the shipped blueprint through HA's actual blueprint/script validators
and execute its actions with mocked calendar and TTS services. They cover English
and Polish, populated/empty days, account and fixed-speaker targeting, backend
failure, malformed responses, TTS failure, repeated invocation without stale
summary reuse, and the manual Google integration exposure allowlist.

Manual acceptance checklist for a disposable HA/backend setup:

1. Validate configuration and run the configured script in HA. Compare the spoken
   summary with today's seeded calendar; confirm the selected speaker plays it.
2. Repeat with an empty day/workspace. Expect a zero-entry summary.
3. Expose only this script, sync devices, and invoke the Google routine from a
   Nest Hub and Nest Audio if available. Expect output on the configured speaker
   in both cases. Record device model/generation, firmware, account region,
   Google assistant/Gemini rollout, HA/TTS versions, and expected/actual results.
4. Stop the disposable backend and invalidate/wait out the calendar cache. Run
   again; expect the failure announcement and a failed script trace.
5. Make TTS unavailable; expect a failed trace with no reroute/retry. Restore it
   and verify a subsequent invocation succeeds.
6. Review the Google exposure list to confirm no unintended scripts were added.

A user-assisted live POC on 2026-09-10 confirmed audible TTS, an audible zero-entry
summary, and Google voice activation of the shortcut. See the
[setup guide verification record](GOOGLE_HOME_SETUP.md#setup-complete) for the
environment and limits. Custom routines, populated-day and failure scenarios,
and the full device matrix remain unverified. Automated results alone are not
evidence of real-device acceptance; the broader checklist above remains pending.
